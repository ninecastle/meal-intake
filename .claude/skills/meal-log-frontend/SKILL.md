# 식단 기록 웹앱 프런트엔드

## 목표
사용자가 1~2주 안에 기록을 포기하는 이유는 입력이 번거롭기 때문이다. 모든 화면은 **"사진 두 장 찍고 확인 한 번"** 으로 끝나야 한다.

## 기술 기본값
- Vite + React + TypeScript, 라우팅은 react-router, 스타일은 Tailwind CSS
- Firebase 모듈식 SDK: `firebase/auth`, `firebase/firestore`, `firebase/ai`, `firebase/app-check`. **Storage·Functions SDK는 쓰지 않는다.**
- 상태는 React 상태 + Firestore `onSnapshot` 구독(별도 상태 라이브러리 생략)
- PWA 매니페스트 추가(홈 화면 설치 → 앱처럼 시연)
- 코드 위치 `web/`, 결과 타입 `web/src/types/analysis.ts`는 `analysis-schema.json`과 1:1로 맞춘다
- 분석·영양값 조회·섭취량 계산은 vision-ai-engineer의 `web/src/analysis/` 모듈을 가져다 쓴다. 화면 코드에서 같은 계산을 다시 구현하지 않는다.

## 화면과 흐름
구글 로그인 → 먹기 전 촬영 → 먹은 후 촬영 → 결과 확인·수정 → 저장 → 하루 요약

1. **로그인**: Google 로그인 버튼 하나. 로그인 상태면 바로 홈으로.
2. **홈(오늘)**: 오늘 섭취 kcal / 목표, 끼니별 카드, 큰 "식사 기록" 버튼. `awaiting_after` 식사가 있으면 맨 위에 "다 드셨나요? 남은 음식 찍기" 카드.
3. **촬영(먹기 전)**: `<input type="file" accept="image/*" capture="environment">`. 안내 한 줄: "수저를 함께, 위에서 찍어 주세요". 끼니 종류는 현재 시각으로 자동 선택. 촬영하면 압축한 사진을 IndexedDB에 임시 보관하고 **즉시** 먹기 전 분석을 호출해, 결과(음식 목록·중량)를 `awaiting_after` 상태로 Firestore에 저장한다.
4. **촬영(먹은 후)**: IndexedDB의 먹기 전 사진을 반투명으로 겹쳐 같은 각도를 유도한다(`getUserMedia` 미리보기가 어렵으면 나란히 표시). 촬영하면 즉시 두 사진을 함께 보내 먹은 후 분석을 호출하고, 성공하면 IndexedDB의 먹기 전 사진을 지운다. 먹기 전 사진이 없으면(브라우저 데이터 삭제 등) 먹기 전 음식 목록 텍스트만으로 분석한다.
5. **분석 중**: 진행 표시, 10초 넘으면 "조금 더 걸려요", 실패 시 수동 입력 안내.
6. **결과 확인·수정**: 음식별 카드(아래 규칙). `needs_review` 항목과 `AI 추정` 항목을 먼저, 노란 테두리로 보여 준다. 저장 버튼 하나.
7. **하루 요약**: 그날 `done` 식사를 쿼리해 화면에서 합산한 총 kcal·탄·단·지, 끼니별 막대, 식사 목록(음식 이름과 kcal, 사진 없음). 날짜 좌우 이동.

## 결과 수정 규칙
- 카드 필드: 이름, 중량(g), 남긴 비율 슬라이더(0~100%), 섭취 kcal, 탄·단·지, 같이 먹은 인원수 선택(1·2·3·4·5+, 기본 1), 출처 배지.
- 출처 배지: `db` → "DB", `search` → "검색 기반", `ai_estimate` → "AI 추정", `user_input` → "직접 입력".
- `검색 기반` 항목은 Gemini 응답의 검색 추천(`searchEntryPoint.renderedContent`)을 사용 조건대로 카드 안에 그대로 렌더링한다. 스타일을 바꾸거나 숨기지 않는다.
- 음식 추가(빈 카드 → 이름 입력)와 삭제(스와이프 또는 삭제 버튼)를 지원한다.
- **이름 수정**: 입력 중 앱에 포함된 식약처 DB JSON으로 자동완성 목록을 보여 준다. 이름이 확정되면 `resolveNutrition(name)`으로 DB → 검색 → AI 추정 순서로 100g당 값을 다시 받고, 중량·남긴 비율은 그대로 둔 채 섭취 값을 다시 계산한다. 사진은 다시 분석하지 않는다.
- **칼로리 직접 수정**: 입력한 값을 그대로 쓰고 `kcal_overridden: true`로 표시한다. 이후 중량·비율을 바꿔도 칼로리는 자동으로 덮어쓰지 않는다.
- **칼로리 수정 후 이름 변경**: "다시 계산할까요?" 확인 창을 띄운다. 예 → 재계산하고 `kcal_overridden: false`, 아니요 → 이름만 바꾸고 직접 입력한 칼로리 유지.
- 나눠 먹는 반찬은 같이 먹은 인원수만 고른다. 별도 공유 토글·전체 인원 스테퍼는 두지 않는다.
- 중량·남긴 비율·인원수를 바꾸면 섭취 값을 즉시 다시 표시한다(공식은 intake-calorie-estimation, 계산 함수는 분석 모듈 것을 사용).
- 3단계 조회가 모두 실패하면 칼로리 입력란에 포커스를 주고 출처를 `직접 입력`으로 둔다.

## 구현 규칙
- **이미지 압축**: 분석 호출 전 canvas로 긴 변 1280px, JPEG 품질 0.8. EXIF 회전은 `createImageBitmap(file, { imageOrientation: "from-image" })`로 처리. 압축한 이미지는 base64로 AI Logic 요청에 넣는다.
- **사진 보관**: 사진은 서버(Storage·Firestore)에 저장하지 않는다. Firestore에는 분석 결과만 쓴다.
- **먹기 전 사진 IndexedDB 임시 보관**: DB `meal-photos`, 저장소 `before`, 키 `mealId`, 값 `{ blob, createdAt }`(압축본). localStorage에는 넣지 않는다.
  - 삭제 시점: 먹은 후 분석 성공 직후(필수). 먹은 후 분석이 실패하면 다시 시도하도록 남긴다.
  - 정리: 앱 시작 시 24시간 지난 항목과 `awaiting_after`가 아닌 식사의 항목, 식사 삭제 시 해당 항목, 로그아웃 시 전부 지운다.
  - IndexedDB를 쓸 수 없으면(사생활 보호 모드 등) 메모리에만 들고 있고, 앱을 닫으면 텍스트만으로 먹은 후 분석을 한다.
  - 먹은 후 사진은 IndexedDB에도 넣지 않는다.
- **저장 순서**: 먹기 전 분석 → meal 문서 생성(`awaiting_after`) → 먹은 후 분석 → 결과 수정 → 저장 버튼에서 `analysis`·`consumedKcal`·`status: "done"`으로 갱신.
- **영양 DB JSON 지연 로드**: 첫 화면 번들에 넣지 않고 결과 화면이나 자동완성 직전에 `import()`나 `fetch`로 불러온다.
- 터치 영역 44px 이상, 한 화면에 주요 버튼 하나.
- 에뮬레이터 연결은 `import.meta.env.DEV`일 때만. AI 호출은 개발 모드에서 목업 응답으로 바꿀 수 있는 스위치를 둔다(무료 한도 절약).

## 녹화·심사 대비
현장 시연은 없다. 피칭 영상과 배포 URL을 제출하고, 심사위원이 며칠 동안 직접 써 본다. 음식 없이 PC에서 체험하는 경우가 많다고 보고 만든다.
- **샘플 사진 체험**: 샘플 전·후 사진을 `web/public/demo/`에 두고, 실제 모델로 미리 분석한 결과(정적 JSON)를 함께 둔다. 운영 빌드에서도 홈과 촬영 화면에 "샘플 사진으로 체험하기"를 잘 보이게 두고, 결과 화면에 "미리 분석한 결과"라고 표시한다. AI 호출 0회로 동작해야 한다. 샘플 사진도 서버에 저장하지 않는다.
- **카메라 없는 PC**: `capture` 속성은 PC에서 무시되므로 같은 입력으로 사진 파일 선택이 된다. 안내 문구는 "촬영하거나 사진을 고르세요"로 둔다.
- **호출 절약**: 같은 사진(압축본 SHA-256)은 기기 IndexedDB 결과 캐시로 다시 호출하지 않는다. 분석 중에는 버튼을 잠그고 식사당 진행 중 요청을 1개로 제한한다. 사용자별 하루 실시간 분석 상한을 넘으면 샘플 체험·직접 입력을 안내한다. 수치와 시그니처는 스펙 5.2절·4.3절을 따른다.
- **한도 안내**: 일일 한도를 다 쓰면 "오늘 AI 분석 한도를 다 썼어요. 매일 17:00(KST)에 다시 열려요"와 함께 직접 입력·샘플 체험을 보여 준다.
- 첫 화면 로딩 2초 이내를 목표로 번들 크기를 확인한다(`vite build` 결과, DB JSON이 첫 번들에 들어가지 않았는지 확인).
