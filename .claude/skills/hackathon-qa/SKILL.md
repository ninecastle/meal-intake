# 해커톤 통합 QA

## 원칙
모듈이 완성될 때마다 바로 검사한다. 마지막에 한 번 몰아서 하면 11/4~11/5에 고칠 시간이 없다. 파일이 있는지가 아니라 **실제 값이 경계를 넘어 그대로 전달되는지** 본다. 기준은 프로젝트 `CLAUDE.md`의 "확정 결정 사항"이다.

## 모듈별 점검표

### A. 분석 모듈 (vision-ai-engineer)
- [ ] 샘플 결과 JSON을 `node .claude/skills/intake-calorie-estimation/scripts/validate_analysis.mjs <file>`로 검사해 통과
- [ ] 먹기 전 분석(호출 A) 결과의 `id`와 먹은 후 분석(호출 B) 결과의 `id`가 모두 짝지어짐
- [ ] 반찬 하나의 `eaters=3` 샘플에서 그 항목 섭취 값만 1/3로 반영, 다른 항목은 `eaters=1` 그대로
- [ ] 먹은 후 분석 요청에 먹기 전·후 이미지 두 장이 모두 들어감(요청 내용 로그로 확인). IndexedDB에서 먹기 전 사진을 지운 상태에서는 텍스트만으로 분석되고 경고가 남음
- [ ] 다 먹은 접시, 손대지 않은 접시, 매칭 실패 접시가 각각 ratio 0 / 1 / null(needs_review)로 나옴
- [ ] 계산식 경곗값: 남긴 비율 0 → 섭취 = 100g당 값 × 중량 ÷ 100, 비율 1 → 0. kcal·탄·단·지 네 값 모두 확인
- [ ] 모델 오류를 강제로 내면(App Check 미등록, 잘못된 모델 ID) `ANALYSIS_UNAVAILABLE` 반환 → 수동 입력 전환

### B. 영양값 3단계 조회 (vision-ai-engineer)
- [ ] DB에 있는 이름(예: "김치찌개") → `nutrition_source: "db"`, `db_food_code` 있음
- [ ] DB에 없는 이름 → `search`, 화면에 검색 추천(Search Suggestions)이 원형 그대로 표시
- [ ] 검색 응답 파싱 실패·`NOT_FOUND`·429 모의 → `ai_estimate`
- [ ] 세 단계 모두 실패 모의 → `user_input`, 칼로리 입력란 포커스
- [ ] 개발용 대략값(`korean-food-kcal.json`)으로 계산한 항목이 "DB"로 표시되지 않음
- [ ] 같은 이름 반복 조회 시 두 번째부터 모델 호출 없음(캐시)

### C. 데이터·규칙 (firebase-engineer)
- [ ] 다른 uid로 `users/{uid}/meals` 읽기·쓰기 거부 (`@firebase/rules-unit-testing`)
- [ ] 규칙이 `status`·`mealType` 열거값, `dateKey` 형식, 항목별 `eaters` 범위(1~20), 항목 수 상한, 허용 필드 밖 키를 거부
- [ ] 23:50 KST 식사가 같은 날 `dateKey`로 저장
- [ ] Spark 준수: 저장소에 `functions/`, `storage.rules`, Storage·Functions SDK import가 없음 (`grep -rE "firebase/(storage|functions)" web/src`)
- [ ] 사진 서버 미저장: 저장된 meal 문서에 사진·썸네일·base64·URL 필드가 없음(검증 스크립트의 사진 키 검사 + 문서 크기 확인), localStorage에 이미지 없음
- [ ] IndexedDB 임시 보관(DevTools → Application → IndexedDB `meal-photos`): 먹기 전 촬영 후 항목 1건 생김 → 먹은 후 분석 성공 직후 사라짐, 분석 실패 시 남아 있어 재시도 가능, 먹은 후 사진은 들어가지 않음, 식사 삭제·로그아웃·24시간 경과 시 정리됨

### D. 프런트 경계·결과 수정 (frontend-dev)
- [ ] `web/src/types/analysis.ts` 필드 이름·null 허용 여부가 `analysis-schema.json`과 일치
- [ ] 실제 분석 결과를 화면에 넣었을 때 빈 값·NaN 표시 없음
- [ ] 이름 수정: 자동완성이 DB 이름을 보여 주고, 확정하면 출처·100g당 값이 바뀌며 중량·남긴 비율은 그대로, 모델 사진 호출은 없음
- [ ] 칼로리 직접 수정 → 중량 변경 시 칼로리 유지 → 이름 변경 시 "다시 계산할까요?" 확인(예/아니요 두 경로 모두)
- [ ] 음식 추가·삭제 후 끼니 합계 즉시 갱신
- [ ] 먹기 전 촬영 후 앱을 닫았다 다시 열어도 `awaiting_after` 카드에서 먹은 후 촬영으로 이어짐
- [ ] 분석 실패 시 수동 입력 화면으로 전환
- [ ] `npm --prefix web run build` 성공, 타입 오류 0, 영양 DB JSON이 첫 번들에 없음

### E. 하루 요약 (frontend-dev + firebase-engineer)
- [ ] 화면 합계(kcal·탄·단·지) == 그날 `status: "done"` meal 문서들의 `analysis.totals.consumed` 합 (Firestore에서 직접 읽어 대조)
- [ ] 식사 저장·수정·삭제 직후 요약 화면이 새로고침 없이 갱신
- [ ] `awaiting_after` 식사는 합계에 들어가지 않음
- [ ] 날짜 이동 시 다른 날 기록이 섞이지 않음

### F. 녹화 전 점검·심사위원 관점 점검 (5단계 11/4 기능 동결 이후, 6단계 11/5 최종 배포 직후)
현장 시연은 없다. 11/5 18:00까지 피칭 영상과 URL을 제출하고, 심사위원이 며칠 동안 직접 써 본다. **11/5 17:00 이후에는 실제 AI 호출을 하지 않는다**(그 뒤 한도는 심사위원용). 그 시각 이후 점검은 목업·정적 확인만 한다.
- [ ] 배포 URL에서 휴대폰으로 구글 로그인부터 하루 요약까지 한 끼 기록(시간 측정, 목표 60초 이내). 영상 녹화 경로와 같게
- [ ] 팀과 무관한 일반 Google 계정으로 배포 URL 로그인 성공(OAuth 동의 화면이 테스트 사용자로 막혀 있지 않음)
- [ ] 샘플 사진 체험이 운영 빌드에서 잘 보이고, AI 호출 0회로 결과가 나오며 "미리 분석한 결과" 표시가 있음
- [ ] 카메라 없는 PC 브라우저에서 사진 파일 선택으로 기록 가능
- [ ] 호출 절약: 같은 사진을 다시 고르거나 재시도·뒤로 가기·두 번 누르기를 해도 AI 호출 수가 늘지 않음(DevTools 네트워크 탭으로 센다), 이름을 확정할 때만 호출 D
- [ ] 사용자별 하루 실시간 분석 상한을 넘으면 샘플 체험·직접 입력 안내가 나옴
- [ ] 일일 한도 소진 모의에서 "매일 17:00(KST)에 다시 열려요" 안내와 직접 입력·샘플 체험 경로가 보임
- [ ] 네트워크 느림(DevTools Slow 4G)에서 분석 중 화면 정상
- [ ] 녹화 직전 Gemini 무료 한도 잔량 확인
