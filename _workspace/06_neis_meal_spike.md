# 학교 급식 연동 시험(spike) — 나이스 교육정보 개방 포털 (2026-10-27, 리더)

새 기능 후보(사용자 제안). 앱에는 아직 넣지 않았다. 시험 스크립트는 `spike/neis/`(`neis_call.py`: 인증키 없이 호출해 JSON 저장, `neis_cors.mjs`: 배포본 도메인에서 브라우저 fetch). 요청에는 학교 이름·날짜만 넣었고 사용자 정보는 넣지 않았다.

## 결론
| 확인 항목 | 결과 |
| --- | --- |
| 브라우저에서 직접 호출(CORS) | **된다.** https://meal-intake-2026.web.app 에서 헤드리스 Chrome `fetch`로 급식·학교 API 모두 200, JSON 읽기 성공, 콘솔 CORS 오류 없음. 서버 응답 헤더 `Access-Control-Allow-Origin: *`(Python에 Origin을 붙여 확인). HTTPS 지원 |
| 인증키 | 인증키 없이도 응답한다(샘플 키). 단 **`pSize` 5 고정·`pIndex` 1 고정, "실제 호출에는 인증키를 사용"하라고 안내**(서비스 설명 페이지). 하루 한 학교 한 끼는 1건이라 기능 자체는 키 없이도 돌지만, 운영(심사 기간)은 인증키를 쓰는 것이 맞다 |
| 인증키 발급 | open.neis.go.kr에서 소셜 계정(구글·카카오·페이스북·네이버)으로 로그인 → 인증키 신청. 무료. 호출 한도·신청 제한 횟수는 공개 페이지에 적혀 있지 않음(발급 후 확인) |
| 학교 코드 찾기 | **된다.** `schoolInfo?SCHUL_NM=서울고등학교` → `ATPT_OFCDC_SC_CODE`(시도교육청 코드, 예 B10) + `SD_SCHUL_CODE`(학교 코드, 예 7010083). 부분 검색 가능("서울" → 651곳), 지역(`LCTN_SC_NM`)·학교 종류(`SCHUL_KND_SC_NM`)로 구분해 보여 줄 수 있음. 급식 조회에는 **두 코드가 모두** 필요 |
| 급식 응답 형식 | 한 끼 = 한 행. 메뉴 이름은 목록, **칼로리·탄단지는 한 끼 합계만**(메뉴별 값·중량 없음). 아래 표 |
| 이용 조건 | 이용 허락 범위 "제한없음", 적재 주기 매일 |

## 급식식단정보 `mealServiceDietInfo` 응답(실제 예: 서울고 2026-10-27 중식)
| 필드 | 형식 | 예 |
| --- | --- | --- |
| `MMEAL_SC_CODE` / `MMEAL_SC_NM` | 1 조식 · 2 중식 · 3 석식 | `2` / `중식` |
| `MLSV_YMD` | YYYYMMDD | `20261027` |
| `DDISH_NM` | 메뉴 이름을 `<br/>`로 이은 한 문자열. 이름 뒤 괄호 숫자는 알레르기 식재료 번호(1 난류, 2 우유, 5 대두 …) | `마제소바 (5.6.10.13.18)<br/>두부장국 (5.6)<br/>참나물무침 (5.6)<br/>야끼만두버무리 (…)<br/>함박스테이크 (…)<br/>파김치 (9.13)` |
| `CAL_INFO` | 한 끼 합계 kcal 문자열 | `932.2 Kcal` |
| `NTR_INFO` | 한 끼 합계 영양소를 `<br/>`로 이은 문자열, "이름(단위) : 값" | `탄수화물(g) : 133.4<br/>단백질(g) : 40.6<br/>지방(g) : 25.4<br/>비타민A(R.E) : …<br/>칼슘(mg) : …` |
| `MLSV_FGR` | 급식 인원 | `1316.0` |
| `ORPLC_INFO` | 원산지 | (쓰지 않음) |

- 호출: `?ATPT_OFCDC_SC_CODE=B10&SD_SCHUL_CODE=7010083&MLSV_YMD=20261027&MMEAL_SC_CODE=2&Type=json`. 기간 조회(`MLSV_FROM_YMD`·`MLSV_TO_YMD`)도 된다. 자료 없으면 `RESULT.CODE = INFO-200`.
- **데이터 품질 주의:** 같은 학교 10/19 중식이 `2964.0 Kcal`, 탄수화물 526.2g으로 나왔다(다른 날은 588~999kcal). 한 사람 한 끼로 보기 어려운 값이 섞여 있으니 범위 검사(예: 300~1,500kcal, 탄단지 kcal 합과 크게 어긋나면 버림)가 필요하다.
- 값은 학교 급식 1인 기준량(배식 기준)이라 실제 배식량·먹은 양과는 다르다.

## 사용자 구상에 비춰 본 점(넣는다면)
- **학교 등록:** 학교 검색 → 고르면 `ATPT_OFCDC_SC_CODE`·`SD_SCHUL_CODE`·학교 이름을 `users/{uid}`에 저장(규칙 `hasOnly(['goal'])`에 키 추가와 규칙 테스트 필요). 학교는 미성년 사용자의 소속을 드러내는 정보라 선택 사항으로 두고 안내 문구를 둔다.
- **인증키:** 서버(Functions)가 없어 키가 클라이언트 번들에 그대로 보인다. 무료 키라 피해는 작지만 남이 써서 한도에 걸릴 수 있다. 하루 한 학교 한 끼 조회 결과를 기기에 캐시해 호출을 줄인다.
- **Gemini 후보 이름:** `DDISH_NM`을 `<br/>`로 나누고 괄호 알레르기 번호를 지운 이름 목록을 호출 A에 후보로 준다(프롬프트 버전 올림). 메뉴별 kcal이 없으니 영양값은 지금처럼 DB → AI 추정으로 찾는다.
- **보정:** 한 끼 합계 kcal·탄단지로 먹기 전 양을 보정하는 방식(예: 사진에서 추정한 먹기 전 kcal 합을 급식 합계에 맞춰 각 항목 무게를 같은 비율로 조정)은 데이터 품질 검사를 통과할 때만 쓰고, 출처 "학교 급식 정보". 남긴 양은 지금처럼 사진 비교.
- **AI 호출 수:** 급식 조회는 Gemini 호출이 아니라 무료 한도와 무관. 호출 A·B 수는 그대로.
