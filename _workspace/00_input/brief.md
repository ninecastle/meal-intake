# 브리프 — 먹기 전·후 사진 기반 섭취 칼로리 웹앱

- 작성: 2026-10-26 (0단계 환경 준비), 리더(메인 세션)
- 기준 문서: 프로젝트 `CLAUDE.md`의 "확정 결정 사항". 이 문서와 다르면 `CLAUDE.md`가 우선한다.

## 1. 만들 것
먹기 전·후 사진 두 장을 비교해 실제로 먹은 칼로리·탄수화물·단백질·지방을 계산하고, 하루 섭취를 요약하는 모바일 우선 웹앱. 2026-11-05 해커톤 시연·제출.

## 2. 풀려는 문제
- 식단 기록을 시작한 사람 대부분이 1~2주 안에 포기한다.
- 음식을 남기거나 반찬을 나눠 먹는 식사에서는 "실제로 먹은 양"을 계산하기 어렵고, 직접 입력은 번거롭다.
- 모든 결정의 기준: 입력 단계를 줄이는가, 섭취량 정확도를 높이는가.

## 3. 사용자 흐름 (확정)
구글 로그인 → 먹기 전 촬영 → 먹은 후 촬영 → 결과 확인·수정 → 저장 → 하루 요약

## 4. 확정된 기술·정책 결정 (요약)
| 항목 | 결정 |
| --- | --- |
| 요금제 | Firebase Spark(무료)만. Blaze 업그레이드·결제 계정 연결 금지. Cloud Functions·Cloud Storage 없음 |
| AI | Firebase AI Logic + Gemini Developer API(무료 등급), 클라이언트에서 호출 |
| 사진 | 서버(Storage·Firestore)에 저장하지 않음. 먹기 전 사진만 폰 브라우저 IndexedDB에 임시 보관 → 먹은 후 분석 때 두 장 함께 전송 → 분석이 끝나면 IndexedDB에서도 삭제. 먹은 후 사진은 보관하지 않음 |
| 분석 호출 | 먹기 전 촬영 즉시 1회(음식·중량 → `awaiting_after`로 Firestore 저장), 먹은 후 촬영 즉시 1회(남긴 비율, 두 사진 함께) |
| Firestore 저장 | 분석 결과만(음식 이름, 중량, 남긴 비율, 같이 먹은 인원수, 칼로리·영양소, 출처) |
| 영양값 순서 | ① 식약처 식품영양성분 DB(음식 표준데이터 전체, JSON 파일로 앱에 포함) → "DB" ② Gemini Google 검색 그라운딩 → "검색 기반"(검색 추천 표시 UI 포함) ③ 검색 실패·무료 한도 초과 → Gemini 자체 추정 → "AI 추정" |
| 계산식 | 섭취 값 = 100g당 값 × 추정 중량(g) ÷ 100 × (1 − 남긴 비율) ÷ 같이 먹은 인원수(기본 1). kcal·탄·단·지 모두 같은 식 |
| 하루 요약 | 서버 집계(`daily/*`) 없이 클라이언트가 그날 기록을 불러와 합산 |

## 5. 결과 수정 규칙 (확정)
- 음식별로 이름·중량·남긴 비율·칼로리를 고칠 수 있고, 음식을 추가·삭제할 수 있다.
- 나눠 먹는 반찬은 음식별 "같이 먹은 인원수"(기본 1)만 고른다.
- 이름 입력 시 DB 자동완성. 이름이 바뀌면 ①→②→③ 순서로 다시 계산하고 중량·남긴 비율은 유지한다(사진 재분석 없음).
- 칼로리를 직접 고친 뒤 이름을 바꾸면 "다시 계산할까요?"라고 확인한다.
